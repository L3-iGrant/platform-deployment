# Values reference

This page lists every value of the chart, what it does and its default.

[Back to the contents](../README.md#contents)

[values.yaml](../values.yaml) has the defaults with a short comment for each key; [values.schema.json](../values.schema.json) checks the values (Helm refuses an unknown value or a wrong type). Each component also has `image`, `resources`, `podSecurityContext`, `containerSecurityContext`, `priorityClassName`, `nodeSelector`, `tolerations`, `affinity` and `imagePullSecrets` (added to `global.imagePullSecrets`). `<fullname>` is the prefix of the object names: the release name, or `fullnameOverride`.

## Global and exposure

| Value | Description | Default |
| --- | --- | --- |
| `fullnameOverride` | The prefix of the object names (`<fullname>`). Empty: the release name | `""` |
| `nameOverride` | The value of the label `app.kubernetes.io/name`, which is also in the selectors. Kubernetes does not let an upgrade change a selector | `""` (the chart name `platform`) |
| `global.imageRegistry` | Registry of the iGrant.io images. An image with its own `registry` does not use it (see [Images](images.md)) | `europe-docker.pkg.dev/jenkins-189019/igrant-customers` |
| `global.imageTag` | The release tag of the iGrant.io images (`api`, `gateway`, `consent-management-backend`, `eudi-wallet`, `dashboard`, `openbao`). Required: the render stops with `global.imageTag is required: the release tag of your version`. An image with its own `tag` does not use it | `""` |
| `global.imagePullSecrets` | Image pull Secrets of all pods. Create them before the install (see [Install](install.md#step-1-the-namespace-and-the-registry-access)) | `[igrant-registry-creds]` |
| `global.imagePullPolicy` | `imagePullPolicy` of all images; `<component>.image.pullPolicy` overrides it | `IfNotPresent` |
| `global.storageClass` | Storage class of all volumes (`""`: the default class, `"-"`: none) | `""` |
| `global.publicScheme` | The scheme of the public URLs | `https` |
| `global.priorityClassName`, `.podSecurityContext`, `.containerSecurityContext`, `.nodeSelector`, `.tolerations`, `.affinity`, `.labels` | Settings of all pods and objects (the priority class must exist; the labels go on all objects). `global.podSecurityContext` and `.containerSecurityContext` apply to each pod and container under the value of the component: a key of the component replaces the same global key as a whole, and each other global key stays, for example `seLinuxOptions` or `supplementalGroups`. The notes of the release name each global key that a component also sets (see [Security settings of the containers](security-context.md#change-the-settings)) | empty |
| `<component>.podSecurityContext`, `.containerSecurityContext` | The security settings of the pods and the containers of `database` (the bundled server and the init hook), `nats`, `redis`, `api`, `gateway`, `consent`, `openbao`, `organisationWallet` and `enterpriseDashboard`; the hooks and Jobs have `api.jobs.*`, `consent.jobs.*` and `organisationWallet.jobs.*`. Each default: a non-root user with a fixed UID and GID, `fsGroup` for the Secret files (mode `0440`) and the data volumes, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `capabilities.drop: [ALL]`, seccomp `RuntimeDefault`, and for the api, consent and the dashboard (port 80) the sysctl `net.ipv4.ip_unprivileged_port_start=0`. Helm merges your keys into the default; `null` removes a key. On OpenShift, set `runAsUser`, `runAsGroup` and `fsGroup` of each component to `null` (the SCC sets them). See [Security settings of the containers](security-context.md) | api, gateway, consent, wallet `65532`; dashboard `101`; PostgreSQL `999`; NATS `65532`; OpenBao `10001`; Valkey `999:1000` |
| `<component>.strategy`, `.minReadySeconds` | The rollout of the Deployments of `api` (also the webhook handler), `gateway`, `consent`, `enterpriseDashboard` and `organisationWallet` (the service and config roles): `RollingUpdate`, new pods are ready before old pods stop. A new pod counts as available `minReadySeconds` after it is ready, so a pod that fails just after its start stops the rollout before an old pod stops (see [Security settings of the containers](security-context.md#the-stop-of-a-pod)) | `maxSurge: 25%`, `maxUnavailable: 0`; `30` |
| `api.server.preStopSeconds`, `gateway.preStopSeconds`, `consent.server.preStopSeconds`, `enterpriseDashboard.preStopSeconds`, `organisationWallet.server.preStopSeconds` | The preStop sleep of the HTTP pods (the sleep action): the pod serves on while Kubernetes removes it from the endpoints. With `.terminationGracePeriodSeconds` (the render checks the stop budget) | `10`; grace periods `40`, `40`, `40`, `30`, `45` |
| `api.server.drainSeconds`, `.gracefulShutdownSeconds`, `.terminationGracePeriodSeconds`; the same keys in `gateway` and `consent.server` | The stop of the Go servers. At SIGTERM `/readyz` answers 503 and the server still accepts for `drainSeconds` (`Server.drainSeconds`, the gateway `Gateway.drainSeconds`), then it waits at most `gracefulShutdownSeconds` for the requests in progress (the api also for the NATS drain, consent also for the NATS drain and the outbox relay). The render stops when `terminationGracePeriodSeconds` is below preStopSeconds + drainSeconds + gracefulShutdownSeconds + 5 | `5`, `20`, `40` |
| `organisationWallet.server.gracefulShutdownSeconds`, `.backgroundShutdownSeconds`, `.terminationGracePeriodSeconds`; `enterpriseDashboard.terminationGracePeriodSeconds` | The stop of the wallet service and config pods: after the preStop sleep, the server waits at most `gracefulShutdownSeconds` for the open requests, then at most `backgroundShutdownSeconds` for the background tasks; the render stops when the sum is not below `terminationGracePeriodSeconds`. The dashboard: nginx ends the requests in progress at `SIGQUIT`; the render stops when the grace period is below preStopSeconds + 10 | `20`, `10`, `45`; `30` |
| `<component>.startupProbe`, `.readinessProbe`, `.livenessProbe` | The probes of `api`, `api.webhook`, `gateway`, `consent` (on the admin port 8081) and `enterpriseDashboard` (the start page `/`). Startup and liveness: `/healthz` (the process runs, no dependency check). Readiness: `/readyz`; the api core, the webhook handler and the gateway check the database every 2 s on one connection outside their pools, and `/readyz` fails when no check passed for 10 s; NATS (the webhook handler: also its JetStream consumers) and the views of the readers are start gates. Consent pings the database through its pool and checks its NATS connection at each probe; its stream and the views of its readers are start gates. The liveness probe starts after the startup probe (see [Security settings of the containers](security-context.md#the-stop-of-a-pod)) | startup 180 s (90 x 2 s); readiness 2 s x 2 with a timeout of 2 s (the webhook handler 5 s x 2; the dashboard 5 s x 3, timeout 3 s); liveness 10 s x 3 |
| `exposure.type` | `ingress` (a `networking.k8s.io/v1` Ingress), `gatewayAPI` (a `gateway.networking.k8s.io/v1` HTTPRoute to your Gateway) or `none` (only the Services; you make the routes). The chart never installs an ingress controller or a Gateway (see [Exposure](exposure.md)) | `ingress` |
| `exposure.ingress.className`, `.annotations` | IngressClass (empty: the default IngressClass of the cluster) and annotations of every Ingress, free form, for example the settings of your controller or a cert-manager issuer (see `profiles/`) | `""`, `{}` |
| `exposure.gatewayAPI.parentRefs`, `.annotations`, `.timeouts` | The Gateway of every HTTPRoute (required for `gatewayAPI`, for example `[{name: platform, namespace: gateway-system, sectionName: https}]`), the annotations, and the timeouts of the route rules (`{request, backendRequest}`, Gateway API durations such as `3900s`; empty: the default of your implementation) | `[]`, `{}`, `{}` |
| `<component>.host` | Host of `api`, `organisationWallet`, `enterpriseDashboard` (required; the gateway receives every request of the api host; on premise only the wallet host is public, see [Exposure](exposure.md#on-premise-installation)) | `""` |
| `<component>.exposure.*` | The exposure of one host: `type`, `className` (ingress), `annotations`, `path`, `pathType`, `tls.secretName` (ingress), `parentRefs` and `timeouts` (gatewayAPI). Empty `type`, `className`, `parentRefs` and `timeouts`: the values of `exposure.*`. `annotations` are added to `exposure.ingress.annotations` or `exposure.gatewayAPI.annotations`. `pathType`: `Prefix` or `Exact` (gatewayAPI: `PathPrefix` or `Exact`). `tls.secretName`: the TLS Secret of the host in the release namespace; empty: no TLS block (the TLS ends in front of the cluster) | empty; `path: /`, `pathType: Prefix` |
| `clientAddress.header` | A request header that your entry proxy sets to the address of its TCP peer and that a client cannot set (the proxy replaces it), for example `X-Real-IP` with the Envoy Gateway policy of `manifests/envoy-gateway/` or with ingress-nginx. The gateway and the api use the client address for the IP allow-lists of the API keys and for the rate limits. Empty: the address of the TCP peer | `""` |
| `clientAddress.trustedProxies`, `.trustedProxyHeader` | The address ranges (CIDR) of trusted proxies in front of the entry proxy (for example a CDN), and the header in which they send the client address. Set both or none (see [Exposure](exposure.md#proxies-in-front-of-the-cluster)) | `[]`, `""` |
